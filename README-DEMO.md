# 演示模式说明（纯前端，无需后端）

本项目已**移除后端**（Spring Boot / MySQL），全部接口由浏览器内置 Mock 提供：
`src/mock` 在页面内接管 `/api` 请求，因此 `npm run dev` 和 `npm run build` 的产物**都能完整演示**，答辩/验收不需要安装数据库、也不需要启动任何服务器。

## 启动

```bash
cd frontend
npm install      # 首次
npm run dev      # 开发模式，默认 http://localhost:5173
```

构建产物演示：

```bash
npm run build
npm run preview  # 打开终端提示的地址（默认 http://localhost:4173）
```

## 演示账号

| 账号 | 密码 | 身份 | 可看到的内容 |
|---|---|---|---|
| `demo` | `123456` | 普通用户 | 首页、商品市场、详情购买、个人中心（收藏/买到/卖出/我发布的）、发布商品、留言、评价、设置 |
| `admin` | `123456` | 管理员 | 普通用户全部内容 + 左侧「管理」入口（审核、下架、分类占比饼图、分类管理） |

登录入口：顶部「登录 / 注册」或右上角头像 → `/login`。登录态由 Pinia 的 `userStore` 维护，token 持久化在 localStorage，刷新页面不丢失。

也支持自行注册：登录页「注册」→ 邮箱 + 昵称 + 密码 → 验证码输入任意 6 位数字（演示环境不校验）→ 注册成功后用**邮箱 + 密码**登录。

## 演示闭环（推荐讲解顺序）

1. **发布**：`admin` 登录 → 我要发布 → 填名称/价格/分类/地址/简介 → 上传封面图和轮播图（本地 FileReader 转 base64，不落盘）→ 提交。
2. **审核**：切到「管理」→ 待审核列表最上方就是刚发布的商品 → 点「通过」。
3. **上架**：回到商品市场 → 刷新/翻页 → 刚发布的商品出现在列表 → 点开详情能看到封面、轮播图、描述、卖家。
4. **下单**：详情页「购买」→ 生成订单 → 第二步显示支付方式。
5. **支付/收货**：个人中心「我买到的」→ 新订单可「去支付」，已发货订单可「确认收货」，也可「删除」订单。
6. **收藏**：市场卡片或详情页点收藏 → 「我收藏的」实时出现 → 再点取消。
7. **设置**：个人中心「设置」→ 回填当前资料 → 修改昵称/地址/电话/头像 → 保存 → 个人主页同步显示。
8. **留言**：进入 `/goods/10`（demo 自己发布的零食大礼包）→ 能看到张同学、李同学的留言；用 admin 登录给任意商品留言，再回 demo 的「个人中心 - 消息留言 - 我收到的」查看。
9. **编辑与上下架**：个人中心「我发布的」→ 编辑（`/publish?edit=id` 自动回填）→ 保存后重新进入审核；或先「下架」再「上架」，观察商品市场的变化。
10. **订单详情与评价**：个人中心「我买到的」→ 订单行点「详情」→ `/order/9002` 看状态时间线 → 「确认收货」→ 打 5 星并提交评价 → 回到商品详情页底部能看到「买家评价」。
11. **卖家主页**：任意商品详情页点卖家卡片 → `/seller/2001` 看信用、在售/已售统计与 TA 的在售闲置。
12. **搜索页**：页头搜索框输入「键盘」→ `/search?keyword=键盘`，可看热门词、最近搜索与结果分页。
13. **分类管理**：`admin` 登录 → 管理端「分类管理 ›」→ `/admin/category` 新增/改名/删除分类；有商品的分类删除按钮置灰。
14. **注册与登录**：注册新邮箱 → 用邮箱+密码登录（新账号收藏/订单/发布为空）。

## 演示覆盖范围

- **首页** `/welcome`：推荐商品来自 `/commodity/getCommodity`，分类导航、搜索、价格筛选与排序、加载更多、收藏入口
- **商品市场** `/shop`：商品来自商品库中状态为「通过」的记录、分类筛选、关键词搜索、价格/时间排序、分页、收藏
- **商品详情** `/goods/:id`：独立路由页，轮播图、描述、发货地址、卖家信息、收藏数、留言板、买家评价、下单 → 支付两步流程
- **卖家主页** `/seller/:id`：卖家信用与在售/已售统计、TA 的在售闲置，详情页卖家卡片进入
- **订单详情** `/order/:id`：状态时间线、支付/发货/收货操作、买家 5 星评价
- **搜索页** `/search`：热门搜索词、最近搜索（localStorage）、结果分页与空状态
- **登录注册** `/login`：独立路由页，邮箱注册、验证码、登录、错误提示
- **发布商品** `/publish`：独立路由页，本地选图、提交后进入管理员审核队列；`?edit=id` 可编辑回填
- **个人中心**：收藏 / 买到 / 卖出 / 我发布的四个列表，数字与列表实时一致；我发布的支持编辑 / 下架 / 重新上架
- **消息留言** `/customer?tab=10`：我收到的 / 我发出的留言，可跳转商品
- **管理端**：审核（通过/驳回）、下架、搜索筛选分页、商品分类占比饼图、分类管理
- **账号**：登录、注册、退出，管理入口按权限显示，登录态由 Pinia 统一维护

## 数据行为

- Mock 状态保存在**浏览器内存**，并自动持久化到 localStorage（`xm:mock-state:v1`）：**刷新页面数据保留**，同一页面内切换账号数据共享。
- 存储空间不足时自动降级（例如上传了大量图片）：商品文字数据保留，上传图片可能不保留，控制台会提示。
- 需要恢复初始数据：控制台执行 `window.__xmResetMock()`，或清除浏览器 localStorage。
- 新发布的商品、审核结果、收藏、订单、留言、评价、分类改动都只存在于当前页面会话。
- 演示图片位于 `public/demo/`，构建时复制到 `dist/demo/`；Mock 启动时通过 `src/mock/images.js` 读成 base64 并缓存。
- 调试：控制台可执行 `window.__xmHttp({ method: 'get', url: '/commodity/getCommodity' })` 直接调接口。

## 已知边界

- **刷新保留**：状态持久化在 localStorage，刷新/关闭再打开都保留；只有清缓存或执行 `window.__xmResetMock()` 才会回到初始数据。
- **纯前端演示**：所有数据都是 Mock，支付、验证码、邮箱都是模拟；不产生真实交易。
- **接真实后端**：把 `src/api/request.js` 里的自定义 adapter 去掉、恢复 baseURL，即可切回真实接口，页面代码无需修改。
