# 演示模式说明（无需后端，全流程闭环）

本项目默认以**演示模式**启动：所有接口由 Vite 开发服务器的 Mock 中间件接管，**不启动 Spring Boot、不连接 MySQL** 也能走通完整业务闭环。
Mock 数据保存在 dev server 内存里，**刷新页面不会丢，重启 dev server 才会重置**。

## 启动

```bash
cd frontend
npm install      # 首次
npm run dev
# 浏览器打开 http://localhost:5173
```

## 演示账号

| 账号 | 密码 | 身份 | 可看到的内容 |
|---|---|---|---|
| `demo` | `123456` | 普通用户 | 首页、商品市场、详情购买、个人中心（收藏/买到/卖出/我发布的）、发布商品、设置 |
| `admin` | `123456` | 管理员 | 普通用户全部内容 + 左侧「管理」入口（审核、下架、分类占比饼图） |

登录入口：顶部「登录 / 注册」或右上角头像 → `/login`（独立路由页）。登录态由 Pinia 的 `userStore` 维护，token 持久化在 localStorage，刷新页面不丢失。

也支持自行注册：登录页「注册」→ 邮箱 + 昵称 + 密码 → 验证码输入任意 6 位数字（演示环境不校验）→ 注册成功后用**邮箱 + 密码**登录。

## 演示闭环（推荐讲解顺序）

1. **发布**：`admin` 登录 → 我要发布 → 填名称/价格/分类/地址/简介 → 上传封面图和轮播图（本地 FileReader 转 base64，不上传服务器）→ 提交。
2. **审核**：切到「管理」→ 待审核列表最上方就是刚发布的商品 → 点「通过」。
3. **上架**：回到商品市场 → 刷新/翻页 → 刚发布的商品出现在列表 → 点开详情能看到封面、轮播图、描述、卖家。
4. **下单**：详情页「购买」→ 生成订单 → 第二步显示支付方式。
5. **支付/收货**：个人中心「我买到的」→ 新订单可「去支付」，已发货订单可「确认收货」，也可「删除」订单。
6. **收藏**：市场卡片或详情页点收藏 → 「我收藏的」实时出现 → 再点取消。
7. **设置**：个人中心「设置」→ 回填当前资料 → 修改昵称/地址/电话/头像 → 保存 → 个人主页同步显示。
8. **留言**：进入 `/goods/10`（demo 自己发布的零食大礼包）→ 能看到张同学、李同学的留言；用 admin 登录给任意商品留言，再回 demo 的「个人中心 - 消息留言 - 我收到的」查看。
9. **编辑与上下架**：个人中心「我发布的」→ 编辑（`/publish?edit=id` 自动回填）→ 保存后重新进入审核；或先「下架」再「上架」，观察商品市场的变化。
10. **注册与登录**：注册新邮箱 → 用邮箱+密码登录（新账号收藏/订单/发布为空）。

管理员还可以：在管理端按「审核状态 / 分类 / 时间」筛选与搜索、下架已通过商品（市场消失、管理端保留「下架」状态）、查看商品分类占比饼图（随商品库实时计算）。

## 演示覆盖范围

- **首页** `/welcome`：推荐商品来自 `/commodity/getCommodity` 接口，分类导航、搜索、价格筛选与排序、加载更多、收藏入口
- **商品市场** `/shop`：商品来自商品库中状态为「通过」的记录、分类筛选、关键词搜索、价格/时间排序、分页、收藏
- **商品详情** `/goods/:id`：独立路由页，轮播图、描述、发货地址、卖家信息、收藏数、留言板、下单 → 支付两步流程
- **登录注册** `/login`：独立路由页，邮箱注册、验证码、登录、错误提示
- **发布商品** `/publish`：独立路由页，本地选图、提交后进入管理员审核队列；`?edit=id` 可编辑回填
- **个人中心**：收藏 / 买到 / 卖出 / 我发布的四个列表，数字与列表实时一致；我发布的支持编辑 / 下架 / 重新上架
- **消息留言** `/customer?tab=10`：我收到的 / 我发出的留言，可跳转商品
- **管理端**：审核（通过/驳回）、下架、搜索筛选分页、商品分类占比饼图
- **账号**：登录、注册、退出，管理入口按权限显示，登录态由 Pinia 统一维护

## 数据行为

- Mock 状态保存在 dev server 内存中：**刷新页面保留**，重启 `npm run dev` 重置为初始数据；
- 新发布的商品、审核结果、收藏、订单、个人资料都只存在于本次 dev server 运行期间；
- 演示图片来自 `mock/assets/demo/`（由 Mock 中间件托管在 `/demo/*`），不进入生产构建产物；
- 已售出的商品（示例数据中 7、8 号）不在市场展示，但仍在「我发布的」和管理端里保留记录。

## 切回真实后端

```bash
# PowerShell
$env:VITE_MOCK=0; npm run dev

# bash
VITE_MOCK=0 npm run dev
```

此时演示 Mock 关闭，`/api/*` 按 `vite.config.js` 的 proxy 转发到 `http://localhost:9080`。前提是后端已启动、MySQL 建库并导入 `backend/sql/transaction_sql.sql`。

## 已知边界

- **演示模式只存在于 `npm run dev`**：`npm run build` 产物不含 Mock，直接静态托管或 `npm run preview` 时 `/api/*` 会返回 `index.html`，页面拿不到数据。答辩/演示请使用 dev 模式。
- 邮箱验证码、支付都是模拟：验证码任意 6 位可通过，支付只返回一段微信支付文案，不产生真实交易。
- 页面中若出现 Element Plus 的废弃 API 警告，属于原项目依赖版本（Element Plus 2.3）的历史提示，不影响演示。

## 相关文件

```
frontend/
├─ mock/
│  ├─ index.js       Vite 插件：注册 /api 中间件、托管 /demo 演示图片、解析请求体
│  ├─ routes.js      接口路由表（37 个端点）与内存中的业务状态
│  └─ data.js        演示初始数据：账号、19 件商品、订单、统计
├─ vite.config.js    按 VITE_MOCK 决定启用 Mock 还是真实代理
└─ src/              页面与组件（发布、设置、个人中心与管理端的少量修复也在此）
```
