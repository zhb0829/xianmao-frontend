# 闲猫二手 · 接口文档

> 适用版本：Vue 3 前端 + 浏览器内置 Mock（`npm run dev` 默认启用）；可按同一接口契约替换为 Spring Boot 后端
> 文档更新时间：2026-11-19

## 一、通用约定

| 项目 | 说明 |
|---|---|
| 基础路径 | `/api`（前端 `src/api/request.js` 中 `baseURL = '/api/'`） |
| 请求方式 | 查询类 `GET`，提交类 `POST`；演示 Mock 对方法不敏感，按路径匹配 |
| 鉴权 | 登录成功后返回 `token`，后续请求放在请求头 `token` 中（不校验大小写） |
| 请求体 | 支持 JSON、`application/x-www-form-urlencoded`、`multipart/form-data`（发布商品用 FormData） |
| 返回格式 | 后端直接返回业务数据本身，不包 `{code,msg,data}`；前端读取 `res.data` |
| 失败约定 | 业务校验按场景返回 HTTP 400/403/404/500 + `{ "error": "错误信息" }`；未匹配路径返回 `false` |
| 金额 | 数字类型，单位元；图片为纯 base64（前端拼 `data:image/Jpeg;base64,` 前缀） |

### 鉴权说明

```http
POST /api/user/login
account=demo&pwd=123456

→ { "token": "mock-token-demo-1730000000000", "id": 1001, "account": "demo", "nickname": "演示同学", "authority": 0, "avatar": "..." }
```

演示账号：`demo / 123456`（普通用户）、`admin / 123456`（管理员，`authority=1`）。
未携带 token 时，Mock 按演示账号 `demo` 处理，保证页面不空白；真实后端会返回 401。

## 二、商品接口

### 1. 查询商品列表

```
GET /api/commodity/getCommodity
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| currentPage | number | 否 | 页码，默认 1 |
| pageSize | number | 否 | 每页条数，默认 9 |
| category | string | 否 | 分类名，如「电子产品」；`all` 或空表示全部 |
| tradeName | string | 否 | 商品名称模糊搜索 |
| priceFlag | number | 否 | 价格排序标记：0 降序，1 升序 |
| timeFlag | number | 否 | 时间排序标记：0 降序，1 升序 |
| status | string | 否 | 商品状态过滤（市场只返回「通过」） |

返回：

```json
{ "records": [{ "id": 1, "tradeName": "iPhone 17 Pro 99新", "price": 6499 }], "pages": 2, "total": 14 }
```

### 2. 查询商品首图

```
GET /api/commodity/getFirstPhoto?commodityId=1
```

返回纯 base64 字符串。

### 3. 查询收藏数 / 当前用户是否收藏

```
GET /api/commodity/getCount?commodityId=1
```

返回：`{ "likeCount": 4, "likeStatus": true }`

### 4. 查询商品详情

```
POST /api/commodity/queryCommodity
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| commodityId | number | 是 | 商品 id |

返回：

```json
{
  "tradeName": "iPhone 17 Pro 99新",
  "price": 6499,
  "description": "自用一年，无磕碰…",
  "sellerId": 2001,
  "sellerName": "张同学",
  "sellerAvatar": "base64…",
  "listingCount": 1,
  "shippingAddress": "广西大学东校园 3 栋",
  "category": "电子产品",
  "time": "2026-10-28 09:12",
  "slideShow": ["base64…", "base64…"]
}
```

### 5. 发布商品

```
POST /api/commodity/launchCommodityInfo
Content-Type: multipart/form-data
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| tradeName | string | 是 | 商品名称，≤30 字 |
| price | number | 是 | 价格，>0 |
| category | string | 是 | 分类名 |
| description | string | 是 | 商品简介 |
| shippingAddress | string | 是 | 交易地址 |
| firstPhoto | string | 是 | 封面图 data URI |
| sellerId | number | 否 | 演示模式下服务端以 token 识别卖家 |

返回：`{ "commodityId": 100 }`，商品状态为「未审核」。

### 6. 保存轮播图

```
POST /api/commodity/saveSlideShow?commodityId=100
Content-Type: application/json
```

```json
{ "base64": ["data:image/jpeg;base64,…", "…"], "id": 12 }
```

返回：`true`

### 7. 删除商品（保留给真实后端）

```
GET /api/commodity/undercarriage?commodityId=100
```

返回：`true`

### 8. 编辑商品

```
POST /api/commodity/updateCommodityInfo
Content-Type: multipart/form-data
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| commodityId | number | 是 | 商品 id（只能改自己的） |
| tradeName | string | 是 | 商品名称 |
| price | number | 是 | 价格 |
| category | string | 是 | 分类 |
| description | string | 是 | 简介 |
| shippingAddress | string | 是 | 交易地址 |
| firstPhoto | string | 否 | 新封面 data URI，不传则保留 |
| slideShow | string | 否 | 轮播图 JSON 字符串（data URI 数组） |

返回：`{ "commodityId": 10, "status": "未审核" }`，编辑后重新进入审核队列。

### 9. 卖家下架

```
GET /api/commodity/offline?commodityId=12
```

返回：`true`，商品状态改为「下架」。

### 10. 卖家重新上架

```
GET /api/commodity/online?commodityId=12
```

返回：`true`，商品状态改为「通过」。

## 四、用户接口

### 12. 登录

```
POST /api/user/login
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| account | string | 是 | 账号（演示账号或注册邮箱） |
| pwd | string | 是 | 密码 |

返回：`{ "token": "…", "id": 1001, "account": "demo", "nickname": "演示同学", "authority": 0, "avatar": "…" }`
失败：HTTP 500 `{ "error": "账号或密码错误" }`

### 13. 注册

```
POST /api/user/register
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| email | string | 是 | 登录邮箱 |
| account | string | 是 | 昵称 |
| password | string | 是 | 密码 |
| code | string | 否 | 前端验证码步骤会提交；当前 Mock 注册端点不校验验证码内容 |

返回：`true`；邮箱已存在时返回 500。演示模式的验证码接口只检查邮箱是否已注册，不实际发送邮件；注册页要求输入 6 位数字，但该验证码不会由 Mock 后端验证。

### 14. 获取邮箱验证码（演示模式不发送和校验）

```
GET /api/user/getCode?email=name@example.com
```

返回：`true`，或 `{ "code": 401, "msg": "该邮箱已注册，请直接登录" }`

## 十、数据层说明（浏览器内置 Mock）

1. 本项目是**纯前端项目**：`frontend/src/mock` 在浏览器内接管全部 `/api` 请求，47 个端点无需 Spring Boot / MySQL / 任何服务器即可使用。
2. 开发模式与构建产物行为一致：`npm run dev`，或 `npm run build && npm run preview`，都能完整演示全部接口。
3. 请求链路：页面 `this.$http` → `src/api/request.js`（自定义 adapter）→ `src/mock/index.js`（路径匹配、参数与 FormData 解析、快照恢复与保存）→ `src/mock/routes.js`（业务路由与运行时内存状态）。
4. 返回格式与真实后端一致：直接返回业务数据本身，不包 `{code,msg,data}`；错误返回 `{ "error": "…" }` 并按业务情况返回 400/403/404/500 状态码。
5. 演示数据保存在浏览器内存并**持久化到 localStorage**（`xm:mock-state:v1`）：**刷新页面保留**；需要恢复初始数据时执行 `window.__xmResetMock()`。演示图片位于 `frontend/public/demo`，由 `src/mock/images.js` 读取为 base64 并缓存。
6. 如后续接真实后端：移除 `request.js` 中的自定义 adapter、恢复 `baseURL` 即可，页面代码与接口字段无需改动。
7. 登录态由 `frontend/src/stores/user.js`（Pinia）维护，请求头 `token` 由 `request.js` 统一注入。
